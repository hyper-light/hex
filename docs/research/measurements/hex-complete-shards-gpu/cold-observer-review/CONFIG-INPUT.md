# Explicit observer artifact/configuration input, source only

Constructor for ROOT's CLI/config owner, after the measured fixed VM cost, native path pair and one SharedCatalog are initialized:

```rust
let guest = GuestRuntime::new(configured_shards, config)
    .with_runtime_cost(cost)?
    .with_runtime_paths(paths)
    .with_gpu_catalog(shared_catalog)
    .with_gpu_observer(input)?;
```

`input: GpuObserverInput` is explicit typed configuration, not a new API/wire/provider inventory. It contains the reviewed evidence digest, the complete artifact list, an exact executable prefix, actual queue/app-array/stderr bounds and an explicit ordinary guest Process Bounds profile. All values come from ROOT's actual build/artifact/loader/profile work. There is no environment/PATH/loader/program/measurement fallback. This code does not invent a glibc, musl, ELF-interpreter or selector-honoring execution contract.

Each GpuArtifact names role, absolute host file, exact absolute Linux guest path, actual byte length and SHA256. Roles distinguish the executable, optional explicit ELF interpreter, Vulkan loader library, ICD manifest, actual driver and dependencies. Required program/loader/ICD roles cannot alias; all guest/host paths are unique. The executable prefix ends at the program artifact and begins with that program or the explicitly supplied interpreter. Any intermediate interpreter arguments are exact reviewed configuration, not generated library search behavior. Every path must map to the SAME configured read-only Share; final symbolic links and special files are refused. Files are streamed to their declared end, checked for extra bytes and compared against before/after held-file identity and SHA256. The fixed64-byte stack buffer is SHA-256's compression-block width, not a growing/tuned memory allowance. The complete declared-configuration encoding is bounded by the existing MAX_CONFIG_BYTES; transient sorted references, paths and Program strings use checked/fallible storage.

This verifies the bytes of the DECLARED set. It does not discover omitted DT_NEEDED/dlopen files, prove host files immutable against outside writers, inspect a compiled ELF's actual interpreter/library closure, or show that a guest transport mounted those exact bytes. ROOT must supply and independently verify the complete pinned loader/ICD/driver/transitive/guest-image closure and a context where that loader honors the selector. A manifest assertion or environment equality is not such evidence. Kernel DRM/virtio_gpu, actual nodes/permissions, headers/libc/architecture, firmware and retained payload paths remain prerequisites. The retained unrelated amd64/glibc witness is not substituted for the new329 producer.

The constructor requires explicit nonzero CPU/memory/process limits and app-array/stderr bounds. The profile must fit the real `allocation.guest() - allocation.cost.guest_overhead`; the allocation is the existing RuntimeCost formula, not a second charge ledger. The exact full configured selector count gives stdout's frozen ABI ceiling40+2649*N. Stdout+stderr must fit the explicit workload memory profile. This is an upper bound check, not a measurement of driver allocations, RSS or native overhead. ROOT still supplies/validates those measurements. GPU backing definition repeats this check against the CURRENT exact initialized allocation before preparing an offer, so changing cost/overhead cannot leave an old observer profile silently admitted.

`GpuObserver::program(N)` fallibly renders the329 producer's five required pairs. The whole guest environment contains exactly VK_DRIVER_FILES=<the pinned absolute single ICD manifest> and VK_LOADER_LAYERS_DISABLE=~all~. There is no inherited PATH, ICD/add-driver/select-disable/layer override, LD_PRELOAD or LD_AUDIT. Actual selector honor and executed driver remain independent requirements. Public configuration accessors expose the same checked profile; they grant no native/guest lifecycle authority.

All inputs/roles/paths/digests/budgets and Bounds presence/value fields participate in a versioned configuration digest. The SAME existing GPU pool key incorporates it (domain v2), beside configured VM paths/cost/selectors. Retained readiness must carry this exact digest and queue bound during the existing preflight barrier. No configured observer means no prepared GPU observer backing or fabricated GPU metadata; CPU preparation remains available. No actual GPU route is initialized by this constructor.

New focused configuration controls are SOURCE ONLY: observer_artifact_bytes_paths_and_clean_program_are_exact; observer_configuration_refuses_alias_unknown_and_uncharged_inputs. Their fake file contents are explicitly hash/mapping models, never executable, driver or measured-resource proof. No build, test, Clippy, native, VM, renderer, driver or GPU result is claimed. Local validation is scoped rustfmt plus git diff --check. The dirty physical consumer/pool identity draft remains excluded from this configuration checkpoint.
