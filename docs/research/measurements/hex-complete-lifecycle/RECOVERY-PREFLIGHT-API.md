The two backing wrappers recheck the whole barrier themselves. No private runtime exposure,
GPU probe, native capacity or fresh placement is used to validate retained state. Unknown
configuration/generation, malformed record/identity or conflicting claims preserves all bytes
and charges. Existing native owners already running are not cancelled by this startup API.

`Recorded::initialize_native` is also public and repeats the full barrier before delegating.
`recover` calls the native initialization hook after its snapshot and before Store cleanup.
`recover_guest_backing` uses the public guarded initializer. `prepare_guest_backing` remains a
read-only barrier followed only by its canonical Prepared publication. WithGuest sends ordinary
rows to their committed route, dedicated guest rows through guest metadata then host native
receipt validation, every Pool through guest then host, and the complete cohort to its host's
native-name cross-check. No map lock spans native I/O.

Windows outliving construction now retains Configured in the existing Keeping mutex; it does not
start a keeper, dispatch an old queued HCS request, or reclaim scratch. Only post-barrier initialization
enters Running. The in-process `WinRuntime::with` constructor keeps its ordinary reclaim behavior.
Outliving cleanup is performed per canonical retained owner after preflight; orphan native marker or
keeper rows refuse and remain preserved, rather than becoming permission for a broad scratch sweep.
The marker read checks exact HCS binding, CPU-only system identity too, outliving ownership, exact
configured scratch and its only permitted cleanup paths, start/init shape, and existing create
request/receipt commitment. Managed Windows receipts check the same 128-bit scope/full original
record commitment without opening/adopting a job or re-opening the physical provider. Later native
kernel-object/membership observations remain necessary and can still refuse if external state changes.
Legacy keeper parsing stays permissive for its old callers; only new read-only startup validation
requires all nonzero fields/no trailing data. Its bounded file buffer is shared with the VM reader.
Marker/scratch and startup keeper paths use fallible construction.

macOS validates the native Process route and any already-present ProcessBox's same scope/identity.
Dedicated/Pool checks accept only the same owned native receipt; a Borrowed PGID observation is not
promoted to cleanup ownership. **Cold active Mac VM recovery remains incomplete until the persistent
helper producer/proxy is sealed**: absence of that native owner refuses before an earlier CPU sibling
is adopted. Prepared/Released missing native metadata is not independently a terminal witness;
its exact backend receipt/configuration preflight is still required. Any PRESENT conflicting receipt
refuses, including on terminal/prepared rows. The helper cannot be inferred from socket or PGID names.

Initialized profile equality currently applies to all retained Pool rows, including Released history;
a changed profile therefore conservatively blocks startup. A historical exception would require
separate exact no-effect/durable-Release semantics and controls. L2's new dedicated GPU Pool metadata
producer/startup wrapper is an additional pending composition dependency, not implemented by a new
inventory/ledger here. Existing HCS marker formats do not commit every legacy workload field; this
extension validates the retained marker/request commitments they actually carry, not a fabricated
native incarnation or a claim of full native effects proof. R01 review still owes inherited serde,
BTreeMap, Runtime classes-vector and legacy constructor/summary allocations. No allocation, latency,
resource, leak or native-correctness completion claim is made.
