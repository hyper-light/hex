Findings:
(i)   Signature and flags above confirmed: the call returns 0 and the cap takes effect. The task's flags
      SET|ACTIVE_FATAL|INACTIVE_FATAL (0x800c, both limits = bound in MiB) and step 2's SET|ACTIVE_FATAL
      (0x8004) BOTH SIGKILL at the cap. priority 40 (a middling jetsam band; the fatal per-process limit
      kills regardless of band).
(ii)  A child capped at N MiB and allocating past it (incompressible fill, so the VM compressor can't
      shrink the pages below the cap) is SIGKILLed (signal 9) at exactly N MiB — 0 overshoot, rootless:
        cap 256 MiB: zombie rusage peak 268435960 B (256.0 MiB), overshoot 0.0 MiB, signal 9
        cap 64 MiB:  zombie rusage peak  67109200 B  (64.0 MiB), overshoot 0.0 MiB, signal 9
(iii) Telling the jetsam fatal-memlimit kill from an ordinary SIGKILL, rootless, before reap:
        a) kqueue EVFILT_PROC with NOTE_EXIT|NOTE_EXITSTATUS|NOTE_EXIT_DETAIL: fflags 0x86000000 —
           NOTE_EXIT and NOTE_EXIT_DETAIL set, but NOTE_EXIT_MEMORY (0x00020000) NOT set. So the kqueue
           memory-exit bit does NOT fire for a per-process fatal-memlimit kill (it is for system memory
           pressure). NOT usable.
        b) proc_pidinfo(PROC_PIDEXITREASONINFO) returns 0 / errno ENOMEM rootless. NOT usable.
        c) proc_pid_rusage(RUSAGE_INFO_V4) on the zombie reports ri_lifetime_max_phys_footprint = the cap
           exactly (preserved after death, readable rootless before reap). USABLE and chosen: an armed
           member seen as a zombie with peak >= its cap was jetsam-killed (sound — reaching the fatal cap
           is death, so a clean exit can never show peak >= cap).

Gotcha recorded: a hog that fills pages with a constant (e.g. memset) is shrunk by the VM compressor so
phys_footprint never reaches the cap and the kill never fires; an xorshift (incompressible) fill is
required. Dead-store elimination at -O2 also hid the writes until a volatile pointer + an escaping sink
were used.
